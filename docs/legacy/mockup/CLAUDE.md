# FLARM FS Monitor System — 要件定義書

**バージョン**: 1.0  
**日付**: 2026-02-25  
**作成者**: Hiroshi Ezoe / Claude

## 1. システム概要

### 1.1 目的

滑空場のフライトサービス（FS）が、FLARM/SkyLens受信ネットワークを通じて離着陸する機体をリアルタイムでモニターし、発航記録を自動生成するWebアプリケーション。

### 1.2 システム構成

```
SkyLens Node (RPi4 + SDR) ──MQTT──→ SkyLens Server (Docker)
                                           │
                                     JSON Stream (FTD-092)
                                           │
                                     FastAPI Backend
                                     - FLARM ID → 機体番号変換
                                     - 離着陸自動検出
                                     - 発航記録管理
                                     - WebSocket配信
                                           │
                                     Web UI (HTML/JS/Leaflet)
                                     - リアルタイムマップ
                                     - ステータスビュー
                                     - 発航記録タブ
```

### 1.3 データソース

- SkyLens JSON Protocol ICD（FTD-092 v0.13）準拠のtrafficメッセージ
- 毎秒配信、MQTT経由

## 2. 定義・判定ロジック

### 2.1 離陸判定

以下の**いずれか**を満たした時点で離陸とみなす：

- 対地速度 ≥ 50 km/h
- 対地高度 ≥ 100ft（滑空場標点の標高を基準）

### 2.2 着陸判定

以下の**両方**を満たした時点で着陸とみなす：

- 対地高度 < 100ft
- 対地速度 < 50 km/h

### 2.3 曳航離脱判定

- 曳航機と被曳航機の座標間距離が **0.08nm以上**に開いた時点で離脱とみなす
- 離脱時の被曳航機高度を発航記録に自動記録

### 2.4 被曳航機の自動認識

- 曳航機の離陸から **1分以内**に離陸した滑空機を被曳航機とみなす
- 曳航機の発航履歴に被曳航機情報を紐付け

### 2.5 教育証明曳航の自動認識

- 曳航中に**下降曳航**（曳航機の高度が有意に低下するフェーズ）が検出された場合、教育証明曳航と判定
- 発航記録の備考欄に自動フラグ

### 2.6 動力滑空機のローパス/タッチアンドゴー判定

- 動力滑空機自身のIGCログの高度パターンから分析
- 着陸判定条件を満たした後、短時間で再度離陸判定が発生した場合 → タッチアンドゴー
- 着陸判定条件に近づくが満たさず再上昇した場合 → ローパス
- 着陸回数を正確にカウント

### 2.7 安全警告（帰還困難判定）

- **滑空場標点からの距離(nm) × 6076 > 対地高度(ft) × 15** の場合、赤表示
- 滑空比15は安全マージン込み（実機性能は25以上）
- 係数はシステム設定で変更可能

### 2.8 通信途絶判定

- **5秒間**受信なしで途絶と判定
- マップ上で最後の受信位置に薄い赤で表示
- 再受信時は通常表示に復帰

## 3. マスターテーブル

### 3.1 機体情報マスター

|フィールド        |型     |説明                             |
|-------------|------|-------------------------------|
|flarm_id     |string|FLARM HEX ID（主キー）              |
|registration |string|登録番号（例: JA01EZ）。不明時はFLARM IDを表示|
|contest_id   |string|コンテスト番号（例：E1）
|owner        |string|所属（クラブ名/個人名）                   |
|aircraft_type|string|機種名（例: LS 8/18m）               |
|category     |enum  |曳航機 / 滑空機 / 動力滑空機 / 一般航空機      |

### 3.2 不明機の自動登録

- マスターに未登録のFLARM IDを検知した場合、自動的にマスターテーブルに追加
- マップ上ではFLARM IDで表示
- 着陸を検知した場合、滑空機発航記録にも自動追記
- 後からFSが機体情報を編集可能

### 3.3 機体情報マスターの設定
- 設定画面から機体情報マスターの設定画面に移行可能
- 機体情報の追加編集削除が可能
- 変更後は直ちに**マップ表示**（アイコン・ラベル）、**ステータスビュー**（登録番号・機種・所属等）、**発航記録**（登録番号・機種・所属・カテゴリ等）のすべてに反映される
- 発航記録の既存レコードも、マスター変更後の情報で上書きされる

## 4. 滑空場設定

### 4.1 基本設定

|設定項目  |説明                       |例                     |
|------|-------------------------|----------------------|
|滑空場名  |滑空場の名称                   |滝川スカイパーク              |
|滑空場標点 |基準座標（lat, lon, elevation）|43.5xxx, 141.9xxx, 115ft|
|R/W方向 |使用滑走路方向の対ペア選択              |01/19〜18/36の18ペアから上下ボタンで選択|
|発航場所A  |R/W方向A（最初の数字）の時の発行座標（lat, lon, elevation）|43.5xxx, 141.9xxx, 35ft|
|発航場所B  |R/W方向B（後の数字）の時の発行座標（lat, lon, elevation）|43.5xxx, 141.9xxx, 35ft|
|安全滑空比 |帰還困難判定の係数（デフォルト: 15）     |15                    |
|途絶判定秒数|通信途絶の閾値（デフォルト: 5秒）       |5                     |
|表示名|登録番号かコンテスト番号をプルダウン選択|コンテスト番号|

### 4.2 R/W方向と発航場所

- R/W方向は対になる2方向のペアで管理する（01/19、02/20、…、17/35、18/36の18ペア）
- 設定画面では上下ボタン（スピナー）1つでペアを選択する（例: ▲を押すと18/36→01/19→02/20…と巡回）
- ヘッダーのトグルスイッチでペア内のどちらの方向を使用中か切り替える（例: 18/36ペアなら「18」か「36」を選択）
- 発航場所は2箇所（R/W方向A・Bに対応）
- その日の風向きにより選択、途中変更可能
- R/W利用方向を選択すると発航場所は1箇所に確定

## 5. マップ機能

### 5.1 機体表示

|条件                |表示                                |
|------------------|----------------------------------|
|通常（1500ft超）       |通常サイズのアイコン                 |
|1500ft以下             |**大きくて濃ゆいアイコン**                |
|帰還困難（距離 > 高度 × 15）|**赤色アイコン**                        |
|曳航機               |**Typeレシプロ機のアイコン**                |
|不明機               |FLARM IDで表示                       |
|通信途絶              |最後の受信位置に**薄い青**で表示、ステータスビューの最上部に表示|

### 5.2 軌跡表示

- 各機体の**過去60秒間の履歴**を線で表示

### 5.3 機体ラベル

- 機体アイコンの横に**登録番号**もしくは**コンテスト番号**を表示（設定に依存）
- 不明機はFLARM IDを表示

### 5.4 地図操作

- 拡大・縮小・回転が自由に可能
- **ホームポジション記録機能**: 1箇所のオフセット位置（中心座標 + ズームレベル）を保存
- ワンクリックでホームポジションに復帰するボタン
- 機体アイコンをクリックすると対象の右側の機体リストが点滅する。他の任意の場所をクリックすると点滅停止。

## 6. 発航記録

### 6.1 タブ構成

|タブ       |内容                |
|---------|------------------|
|曳航機1     |曳航機1号機専用の発航記録     |
|曳航機2     |曳航機2号機専用の発航記録     |
|滑空機・動力滑空機|滑空機と動力滑空機の発航記録（共通）|

### 6.2 曳航機発航記録フィールド

|フィールド |自動/手動  |説明              |
|------|-------|----------------|
|発航番号  |自動     |当日の連番           |
|離陸時刻  |自動     |離陸検出時刻 (JST)    |
|着陸時刻  |自動     |着陸検出時刻 (JST)    |
|被曳航機  |自動     |被曳航機の登録番号（自動認識） |
|離脱高度  |自動(編集可)|曳航離脱時の被曳航機高度 (ft)|
|教育証明曳航|自動(編集可)|下降曳航パターン検出時にフラグ |
|備考    |手動     |給油記録など自由記入      |

### 6.3 滑空機・動力滑空機発航記録フィールド

|フィールド|自動/手動  |説明                  |
|-----|-------|--------------------|
|発航番号 |自動     |当日の連番               |
|登録番号 |自動     |機体登録番号（不明機はFLARM ID）|
|機種   |自動     |マスターから取得            |
|所属   |自動     |マスターから取得            |
|カテゴリ |自動     |滑空機 / 動力滑空機         |
|離陸時刻 |自動     |離陸検出時刻 (JST)        |
|着陸時刻 |自動     |着陸検出時刻 (JST)        |
|飛行時間 |自動     |離陸〜着陸の経過時間          |
|離脱高度 |自動(編集可)|曳航離脱高度 (ft)。動力滑空機は空欄 |
|発航方法 |自動(編集可)|飛行機曳航 / 自力発航（動力滑空機） |
|着陸回数 |自動     |動力滑空機のタッチアンドゴー含む累計  |

### 6.4 発航記録操作

- 各レコードの**追加・編集・削除**が可能
- 離脱高度は自動認識値を手動で修正可能
- 不明機が着陸した場合、自動的に滑空機発航記録に追記
- 発航記録はすべて離陸時刻でソート
- 機体情報マスターが変更された場合、発航記録の登録番号・機種・所属・カテゴリ等のマスター由来フィールドは即座に上書き反映される

### 6.5 データエクスポート

- 1日単位で**CSV/Excel**出力可能
- タブごと（曳航機1/曳航機2/滑空機・動力滑空機）に個別出力

## 7. ステータスビュー

### 7.1 レイアウト

```
┌─────────────────────────────────┐
│ 🔴 通信途絶機 （最後の位置で赤表示）│ ← 最上部
├─────────────────────────────────┤
│ ▲ 上空欄                        │
│   高度高い順に表示               │
│   [登録番号] [機種] [高度]       │
│   ...                           │
├─────────────────────────────────┤
│ ▼ 地上欄                        │
│   曳航機 ← 最上部               │
│   他の機体は発航場所に近い順     │
│   [登録番号] [機種] [所属]       │
│   ...                           │
└─────────────────────────────────┘
```

### 7.2 上空欄

- 上から**高度が高い順**に表示
- 右側に高度を表示
- 帰還困難機は赤表示

### 7.3 地上欄

- **曳航機を最上部**に表示
- その他の機体は**発航場所に近い順**に表示
- 登録番号、機種、所属を表示

### 7.4 通信途絶機

- **最上部**に表示
- 薄い赤で表示
- 最後の受信位置情報を付記

### 7.5 クリック操作
- リストにある航空機登録番号をクリックすると、その航空機アイコンがマップの中心になり点滅する。他の任意の場所をクリックすると点滅が終了。

## 8. データフロー詳細

### 8.1 SkyLens JSON trafficメッセージ（入力）

```json
{
  "traffic": {
    "id": { "flarm": 14503442 },
    "src": { "flarm": {} },
    "type": 1,
    "pos": { "lat": 36.032800, "lon": 139.821267, "alt": 624, "baro": 577 },
    "mov": { "speed": 34.2, "gnd": false, "climb": -5.0, "turn": 0, "track": 12.7 },
    "time": 1732934974.0,
    "rec": [{ "gnd": { "dBm": -65.0, "id": "FS-TAKIKAWA-01" } }]
  }
}
```

### 8.2 TargetType（type フィールド）

|値 |種別                     |
|--|-----------------------|
|1 |グライダー / モーターグライダー / TMG|
|2 |曳航機                    |
|3 |ヘリコプター                 |
|8 |レシプロ機                  |
|9 |ジェット/ターボプロップ           |
|13|UAV/ドローン               |
マップ上の航空機アイコンはこれらのTypeに準じたアイコンにする。

### 8.3 判定に使用するフィールド

|判定    |使用フィールド                  |計算                                           |
|------|-------------------------|---------------------------------------------|
|離陸    |mov.speed, pos.alt       |speed ≥ 13.9 m/s (50km/h) OR alt - 標点標高 ≥ 100ft|
|着陸    |mov.speed, pos.alt       |alt - 標点標高 < 100ft AND speed < 13.9 m/s        |
|曳航離脱  |pos.lat, pos.lon（2機間）    |haversine距離 ≥ 0.08nm                           |
|帰還困難  |pos.lat, pos.lon, pos.alt|標点からの距離(nm) × 6076 > (alt - 標点標高)(ft) × 15   |
|通信途絶  |time                     |現在時刻 - 最終受信時刻 ≥ 5秒                           |
|低高度   |pos.alt                  |alt - 標点標高 ≤ 1500ft                            |
|教育証明曳航|pos.alt（曳航機）             |曳航中に高度の有意な低下を検出                              |

## 9. 開発フェーズ

### Phase 1: シミュレータ + コアエンジン

- IGCファイルベースの複数機体同時シミュレータ
- 離着陸/曳航離脱の自動検出エンジン
- FLARM ID → 機体情報マスターの登録番号かコンテスト番号

### Phase 2: MVP アプリ

- FastAPIバックエンド + WebSocket配信
- リアルタイムマップ（Leaflet）
- ステータスビュー
- 基本的な発航記録（自動生成 + 手動編集）

### Phase 3: 完成版

- 発航記録タブ（曳航機1/2/滑空機・動力滑空機）
- CSV/Excelエクスポート
- 教育証明曳航の自動認識
- 動力滑空機のタッチアンドゴー/ローパス判定
- 不明機の自動登録・記録
- ホームポジション保存機能

### Phase 4: SkyLens実機統合

- SkyLens Server (Docker) との接続
- MQTT受信の実装
- 実環境テスト（滝川スカイパーク）
